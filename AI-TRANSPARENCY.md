# AI transparency — marking and detection of AI-generated text

*Applies to Biblo 1.1.2 and later. Published under Article 50(2) of Regulation
(EU) 2024/1689 (AI Act). Last updated: 2026-08-17.*

Biblo generates synthetic text (chat answers, rewritten prompts) through
third-party large language models. This page documents **how that text is
marked in a machine-readable format when it leaves the application**, and how
anyone can detect the marking.

## What is marked

Whenever AI-generated text is copied to the system clipboard — via a **Copy
button** or by **selecting text and copying it** (Ctrl+C or the context
menu) — Biblo places **two flavours** on the clipboard:

- `text/plain` — the text exactly as displayed, unaltered;
- `text/html` — the same content wrapped in a container element carrying
  provenance metadata (see format below).

Inside the app, every AI-generated answer additionally carries a **visible
label** ("Generated by AI — verify important information") and the chat shows
a permanent notice that the user is interacting with an AI system
(Article 50(1)).

## Marking format

The `text/html` clipboard flavour is wrapped as follows:

```html
<div data-biblo-ai-provenance="1"
     data-ai-generator="Biblo"
     data-digitalsourcetype="trainedAlgorithmicMedia"
     data-digitalsourcetype-uri="http://cv.iptc.org/newscodes/digitalsourcetype/trainedAlgorithmicMedia"
     data-ai-detection="https://github.com/LorenzoMontoli/biblo-releases/blob/main/AI-TRANSPARENCY.md">
  <!--biblo:ai-generated digitalSourceType=trainedAlgorithmicMedia-->
  ...the copied content...
</div>
```

The `digitalsourcetype` value uses the **IPTC Digital Source Type**
controlled vocabulary; `trainedAlgorithmicMedia` is the term the vocabulary
defines for content created by a trained generative model. The HTML comment
is a redundant marker for parsers that strip attributes but keep comments.

## How to detect it

Check the `text/html` clipboard flavour for the `data-biblo-ai-provenance`
attribute (or, more generically, for
`data-digitalsourcetype="trainedAlgorithmicMedia"`). Example, in a browser
console or any Chromium-based environment:

```js
const items = await navigator.clipboard.read();
for (const item of items) {
  if (!item.types.includes('text/html')) continue;
  const html = await (await item.getType('text/html')).text();
  const doc = new DOMParser().parseFromString(html, 'text/html');
  const marked = doc.querySelector('[data-biblo-ai-provenance], [data-digitalsourcetype="trainedAlgorithmicMedia"]');
  console.log(marked ? 'Contains AI-generated text (Biblo)' : 'No Biblo AI marking');
}
```

Any HTML parser (or even a plain substring search for
`data-biblo-ai-provenance`) works the same way; no proprietary tooling is
required.

## Scope and known limits

- The marking states that the copied artifact **contains AI-generated
  text**. Answers produced by Biblo's retrieval-augmented pipeline may
  embed verbatim quotations from the user's own documents (human-authored
  text); the artifact-level marking intentionally does not claim that every
  word is synthetic.
- The `text/plain` flavour is **not** watermarked. Invisible Unicode
  watermarks are trivially destroyed by normalisation and would also
  falsely mark human-authored quotations; statistical text watermarking
  through third-party inference APIs is not available to downstream
  integrators as of the date above. A written technical-feasibility
  assessment documenting this reasoning is kept by the provider.
- Text extracted from the user's scanned documents by OCR is a
  transcription of pre-existing human content, not synthetic content, and
  is therefore not marked.
- Pasting into targets that accept only plain text, or editors that strip
  `data-*` attributes and comments, loses the marking; this is a limitation
  of the receiving software, not of the marking on the clipboard artifact.
